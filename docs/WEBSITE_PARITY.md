# 与原网站的对照：v0.2

目标是让同样的探索材料能通过 Skill 连续使用，而不把聊天工具变成必须部署的服务。

| 能力 | v0.2 的实现 | 仍需区分的地方 |
| --- | --- | --- |
| 24 题基线 | 原题、五档回答、反向题规则全部迁入，支持分批和改答 | 原创反思题，没有新增测量效度 |
| 三套各五轮情境 | 原始叙事、选项、信息、条件、资源变化和自定方案规则 | 演练后果仍是假设规则，不是现实预测 |
| 五主题、四轮访谈 | 原版首问与四轮关注点，宿主 AI 动态追问；保留中断状态 | 不强制重复已知问题，不用 AI 补写用户回答 |
| 15 维模型 | 迁入证据归组、同来源权重上限、情境差异和自述对照规则 | 默认给文字线索，不显示未校准的置信百分比；深度理解依赖宿主 AI |
| 资料进度 | 精确保存题号、节点、访谈轮次；区分完整与部分完成 | 不照搬付费门槛；资料数量不是人格准确率 |
| 完整报告与三位人物 | 原始证据引用、领域差异、关键差异、人物资料与行动比较；结构程序校验及语义复核流程 | 程序不能证明传记真假或个性类比成立。独立复核不可用时明确是自查 |
| 行动与复盘 | 多次尝试、事前预测、实际结果、部分/未尝试、暂停与明确恢复 | Skill 不替用户执行现实行为，不自动发消息或提醒 |
| 保存和断点续接 | 私人 JSON、原子替换、版本冲突保护、重试去重；原始证据可追溯 | 需要执行工具和用户指定档案；纯聊天模式只能人工整理 |
| 资料变更和删除 | 纠正、追加或删除后作废旧报告；删除来源时清除依赖它的行动和重试缓存 | 不会删除宿主聊天、系统备份或已有导出副本 |
| 导入和阅读版导出 | 校验导入原网站 Profile v1；生成当前档案的 Markdown 阅读版 | 不是账户/数据库全量搬迁，不保证反向导回网站 |
| 页面与服务 | 使用聊天交互、表格和本地阅读版 | 没有网站的交互图谱、登录、支付和服务端权限体系 |

## 已验证的内容

`data/catalog.json` 从原网站数据模块导出，迁移时核对了整个对象：24 道题、15 个维度、3×5 个情境节点、5 个经历主题一致。

`tests/website_reference.mjs` 在原网站自己的执行环境中调用原始引擎，生成完全虚构的对照数据。`tests/fixtures/website-reference.json` 保存相关源码的 SHA-256 和结果，不包含私人档案或密钥。

对照覆盖 12 条完整路径、60 次决策：全部固定选项、自定方案、不同信息请求数量；检查资源变化、后果、证据假设、各维度聚合。另对照 24 题正反向计算、多情境聚合及资料采集进度。浮点比较允许 1e-12 级舍入差异。

本地自动测试还覆盖：断点记录、回答修改、未完成状态、重复提交、过期版本、并发写入、情境篡改、访谈归组、行动暂停与恢复、报告错误引用和过期指纹、删除派生内容、原档保护和阅读版导出。所有测试只使用临时目录及合成资料。

另实际调用原网站的 `createDemo()` 生成示例档案，确认可以导入，且原始问卷、三套完整情境、访谈及证据保持一致。两个独立对话试用分别完成了中途续答、离线人物草稿保存；检查实际档案后，确认题号、修正和原有暂停状态均被保留。

## 尚未得到的证明

这些检查验证的是流程、记录和计算规则。**没有用同一批真实用户做网站与 Skill 的效果研究，也没有完成 GLM 与每一种宿主模型之间的报告质量对照实验。** 不能据此宣称认识自己的效果、心理准确度或行为改善已与网站完全相同。

首版做过轻量访谈、离线人物候选和联网人物资料的独立试用；增强版继续检查跨会话续接与结构化报告保存。Claude 客户端仍未实机验证。使用云端临时执行环境时应下载私人档案，再在后续对话明确提供。

## 重新生成网站对照数据

这是维护者流程，不是使用 Skill 的前置要求。需要提供原网站源码目录并使用其 `tsx` 运行环境，从该目录运行本仓库的 `tests/website_reference.mjs`，传入网站目录参数。脚本只读源码、不加载 `.env`、不发网络请求。核对题库一致后，移除输出中的重复 catalog，再更新测试基准。

普通维护验证只需在仓库执行：

```sh
python3 -m unittest discover -s tests -v
```
